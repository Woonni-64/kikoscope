# 图片上传修复（2026-10-29）

## 原因

线上图片上传可复现 HTTP 500：`spawn python3 ENOENT`。服务器图片识别失败后进入 Python 备用路径，而 Vercel Node 环境没有 Python。

## 修改

- 图片先在浏览器使用 Tesseract.js 识别英文，再将文本发往整理接口。不需要图片识别 API 密钥；首次需下载英文识别资源。现有服务端 Gemini 识别保留可配置模型的兼容路径，但线上不再尝试不存在的 Python。
- 增加粘贴原文入口。PDF/Office 无法识别时给出复制原文的提示，不再把二进制内容当正文。
- Vercel 新解析不写项目文件系统。接口返回完整结果，浏览器在跳转前保存；精读、练习和分析页优先读浏览器保存的结果。新结果不能自动跨设备同步，清理站点数据前应备份。
- 增加本机解析JSON备份下载按钮；保留已有词库和旧服务端资料。备份文件当前需保留，未增加一键恢复界面。
- 失败行显示具体原因；全失败时不再弹成功提示；非JSON响应和存储空间不足有对应提示。
- 去掉返回固定演示词汇、无关图书馆题目的逻辑，原题文本仍保留，不声称已自动生成答案。

## 验证

- `npm run build` 通过（包括 TypeScript）。
- `node tests/run-upload-repair.mjs` 通过：使用生产构建并设置VERCEL=1；测试识别文本提交、原始文件名、无固定假题、空文本、识别失败不触发Python、旧资料可读、缓存刷新和存储空间不足。
- Tesseract.js 实际识别合成英文PNG，两句正文均准确返回。
- localStorage（浏览器本地存储）测试为模拟浏览器测试，不是Mac实机或完整浏览器UI验收。
- 原项目 ESLint 配置当前报循环结构错误，未将这项标通过，未为此改动全项目规范。

## 语法解析修复（2026-10-31）

- 删除 localGrammarFallback，不再将通用提示和英文原句作为“中文翻译”返回成功。
- 优先使用服务端 DEEPSEEK_API_KEY；只有未配置 DeepSeek 时才使用 GEMINI_API_KEY / GOOGLE_GENERATIVE_AI_API_KEY。
- 无密钥、鉴权失败、余额不足、限流、超时和空输出均返回明确错误；前端显示原因并提供“重试解析”。不在响应中暴露密钥和上游原始错误。
- 可选 DEEPSEEK_GRAMMAR_MODEL / GEMINI_GRAMMAR_MODEL；默认 deepseek-chat / gemini-2.5-flash。请求限时25秒，最大输入6000字符。
- `node tests/grammar-repair.mjs` 通过，覆盖以上异常和两种提供方的成功响应格式。提供方响应为模拟测试，不代表已验证真实密钥和额度。
- 修复代码上线不等于配置了模型密钥。需要在 Vercel 项目的 Production 环境配置上述任一有效密钥后重新部署，才可实际生成AI解析。
